## 해석과 한계

이 실행에서는 문맥 초과가 실패의 전부였다는 설명을 지지하지 않는다. 기존 문맥 실패 39개는 모두 진단을 제출했으나 30개는 오진이었다. 전체 유형 정확도는 71%지만 유형·위치 공동 성공은 42%로, 유형을 맞히고도 위치를 못 맞힌 사례가 29개다. 특히 misconfiguration은 22개 모두 공동 진단에 실패했다. 위치 판별과 일부 장애 유형의 처리에 문제가 남아 있다는 관측이다. 유형 macro-F1은 원본 Claude와 수치상 비슷하지만 공동 진단 성공은 42/100 대 66/100으로 차이가 남는다. 이 한 번의 실행으로 동등성이나 모델 능력의 상한을 입증하지 않는다.

문맥 처리 결함과 진단 오답을 분리해서 해석해야 한다. 입력 실패 감소는 이 고정 평가에서 어댑터의 수용 가능성 개선을 지지한다. 관측 정보가 보존되어도 압축 문법 이해와 묶음 간 추론은 원래 입력과 다를 수 있다. 그러므로 v2 대비 점수 변화는 입력 표현·문맥 처리 변경을 포함한 전체 에이전트 결과다. 분할 없이 원시 전체 관측을 한 번에 읽는 모델 능력과 같다고 주장하지 않는다.

원본 환경·도구·채점 소스와 스냅샷을 사용했지만, 원본 Docker Linux Python 3.11.14의 전체 orchestration 대신 Windows Python 3.13.2와 직접 FastMCP handler를 사용했다. Jev는 선택형 도구/인자 인터페이스를 쓰며 Claude와 출력 방식이 다르다. 이미 관측한 평가셋의 입력 실패를 수정한 재측정이므로 새 미관측 평가가 아니다. 본 평가 도중 점수에 따라 설정을 바꾸지 않았다. 선택지 순서를 반복 바꾸는 추가 실험은 이번 재측정에 포함하지 않았다.

시나리오 fingerprint 일치는 초기 사례의 동일성을 확인한다. 서로 다른 도구 선택에 따른 이후 관측·동적 난수 흐름까지 같은 값이었다는 뜻은 아니다.

LAYA 학습, 8비트 optimizer, LoRA, Sol/Claude 추가 호출, 외부 리더보드 제출은 미실행이다. 이 결과로 LAYA의 성능을 판단할 수 없다. GPU는 로컬 모델 학습·추론에 사용하지 않았다.

## 시간과 비용

평균 에피소드 76.85초. 본 평가 API 대기 시간 합계 651.51초는 동시 요청을 합산한 값이다. 요청 속도 제한과 로컬 압축·실행 시간을 포함하므로 Claude 모델 자체 속도와 직접 비교하지 않는다.

도구 선택·인자 선택·증거 분할이 각각 API 요청을 쓰므로 요청 수는 환경 단계 수와 다르다. 최대 환경 100단계/solver 100 turn 예산을 늘린 것은 아니다.
