# 재실험 v2: 신뢰도 및 네트워크 지표 프로토콜

실행 식별자: reliability_v2_20261008. 기존 PoC 결과와 별도 보관한다.
수치와 최종 결론은 실행 완료 후 생성하는 결과 보고서를 따른다.

## 검증 질문

1. 내부 장애 상태를 제거해도 도구 기반 진단을 학습하는가?
2. 동일 정보·행동·데모·평가 시나리오에서 GNN과 MLP가 어떻게 다른가?
3. 진단 가중치/샘플링의 효과가 단순 추가 학습의 효과를 넘는가?
4. 크기 증가, 토폴로지 계열 변화, 경미한 장애, ID 순서 특징 교란에서 유지되는가?
5. 정확도, 오진/미진단, 도구 비용, 지연, 연결 실패와 어떤 관계가 있는가?

## 사전에 고정한 조건

- 학습: Star 4/5/6 각각 700개, 장애 4종 각각 175개 성공 Rule 데모.
- 3개 정책 학습 seed: 11, 22, 33. 모든 모델에 동일한 데모를 제공한다.
  이는 고정 데이터셋에서의 초기화·최적화 변동성이다. 데이터셋 seed의 변동성까지 검증하지 않는다.
- 학습 데이터는 300000 계열, 평가 데이터는 900000 계열 seed로 분리한다.
- 조건당 200개 평가 사례, 장애별 50개. 모든 모델/seed에 같은 사례를 제공한다.
- Star 6/8/10/12, Linear 6, Mesh 6, Random 6, 경미한 장애 Star 10.
- 기본 지연 장애 10–20배, 경미한 조건 2–5배. 나머지 장애 생성은 동일하다.
- 공통 행동 예산 40회. 성공까지 단계의 누적 분포를 별도 제공한다.
- 초기 BC: ceil(데모 transition 수/64) × 80 optimizer updates.
- 추가 학습 4개 군: 각각 ceil(transition 수/64) × 40 updates.
  무가중 추가 학습 / 진단 종류 loss ×4 / 진단 샘플 확률 ×3 / 두 개 결합.
  샘플링 군도 업데이트 수는 동일하다. 기존 “샘플 복제 후 같은 epoch”와 다르다.
- 각 학습 seed의 동일 baseline 체크포인트에서 추가 학습을 시작한다.
- CPU, PyTorch 단일 스레드, 결정적 연산. 버전과 소스/모델 SHA-256 기록.
- 진단 종류와 위치가 모두 맞아야 Exact. 링크/성능 장애의 방향 교환은 원본 판정과 같이 허용.
- 테스트 결과를 보고 epoch·seed·가중치를 선택하지 않는다. 마지막 고정 update 모델을 평가한다.

## 정책에 허용하는 정보

사전에 알려진 장비 목록과 명목상 연결 목록을 가진 네트워크 운영 환경을 가정한다.
이는 미탐색 토폴로지 발견 과제와 다르다. 목록에는 상태, 지연, 장애 유형·위치가 없다.

PublicView는 관측, 명목 토폴로지, 행동 목록, 단계 수만 노출한다.
실제 링크 상태와 관측하지 않은 지연의 내부 조회를 제거한다.
Rule 역시 실제 링크 up/down 대신 도구 관측만 사용한다.
정답은 평가와 성공 데모 선별에만 사용하며 정책·특징·행동 선택에 전달하지 않는다.
GNN/MLP는 동일한 그래프 텐서와 pointer 행동을 사용한다. MLP는 최대 12개 노드/132개 유향 edge를
입력하는 새 비교 모델이다. 과거 Star 전용 padded MLP와 동일 모델이 아니다.
Rule은 전체 도구 이력을 사용하는 교사이며, 학습 모델과 동일 용량의 모델 비교 대상은 아니다.

정규화된 ID 순위 특징은 유지하되 Generic에서 에피소드마다 순위 값을 무작위 재배치하는
추가 평가를 한다. 이는 **순위 특징 의존도 검사**이며, 장비 ID를 실제로 바꾸거나 그래프를
동형 치환하는 완전한 permutation equivariance 검사는 아니다.

## 지표와 해석

| 영역 | 지표 | 해석/제약 |
|---|---|---|
| 진단 | Exact, 유형 정확도, 엄격한 위치 정확도, 유형별 precision/recall/F1, macro F1, 혼동행렬 | 미제출은 유형 recall의 실패로 포함 |
| 실패 | 오진 제출률, 미제출 timeout, 제출률, 제출한 경우의 정확도 | false positive는 정상 데이터의 오탐률과 구분 |
| 비용 | tool 호출 수, 반복 호출률, 잘못된 행동률, 시뮬레이터 상대 도구 비용 | 상대 비용은 바이트·달러·실제 트래픽 부하가 아님 |
| 시간 | 성공 시 진단 단계, 성공 누적 단계 분포, CPU 정책 결정 ms, 에피소드 wall ms | 정책 실행시간과 네트워크 지연은 별개 |
| 발견 | 발견한 장비 비율 | scan 한 번으로 대부분 100%가 되어 단독 지표로 불충분 |
| 네트워크 | 모든 ordered pair의 ping 실패율, 성공 ping 지연 p50/p95, 동일 pair 연속 지연 차의 절댓값 | 모델 행동과 독립된 진단 전 공통 측정 |
| 손실 | 명시적 송수신 카운터가 있는 ping의 패킷 손실률 + 카운터 제공 비율 | 장비 down 결과는 카운터가 없어 제외됨. 전체 손실률로 해석 금지 |
| 용량 | 경로의 최소 설정 bandwidth | 설정 용량이며 처리량/굿풋이 아님 |
| 영향 | 동일 장애 인스턴스와 장애를 제거한 반사실 네트워크의 지표 차 | 실제 복구 실행이나 MTTR 측정이 아님 |
| 일반화 | 크기·계열·경미 장애·순위 특징 교란별 Exact와 비용 | unseen 조건에 대한 단일 성능 평균으로 축약하지 않음 |

네트워크 측정은 별도 ToolSimulator와 독립 RNG로 모든 노드 쌍당 5회 시행한다.
학습 정책은 이 측정값을 받지 않는다. 진단 도구의 잡음은 사례/행동/동일 행동 반복 번호로
고정하므로 모델이 같은 도구를 같은 대상에 호출했을 때 같은 잡음을 받는다.

원본 ping은 경로 지연 합에 ±10% 잡음을 더한다. 패킷 수준 큐잉/트래픽/혼잡 제어 모델이 아니다.
따라서 RFC 표준의 one-way delay, IPDV 및 실제 패킷 손실 실험을 수행했다고 주장하지 않는다.
참고 정의: [RFC 7679](https://www.rfc-editor.org/info/rfc7679/),
[RFC 7680](https://www.rfc-editor.org/info/rfc7680/),
[RFC 3393](https://www.rfc-editor.org/info/rfc3393/).

## 불확실성과 결과 보존

- 학습 seed별 수치를 모두 저장하고 평균±표준편차를 보고한다.
- 개별 모델/seed의 Exact는 Wilson 95% 구간을 제공한다.
- 모델 차이는 학습 seed와 공통 사례를 재표본화하는 paired bootstrap 95% 구간을 제공한다.
  seed 3개로 구간이 안정적으로 확립되는 것은 아니며 다중 비교 보정은 하지 않는다.
- 같은 사례를 seed마다 재사용하므로 600개 독립 네트워크 사례처럼 해석하지 않는다.
- 네트워크 원자료는 사례별 JSONL, 진단 원자료는 모델·seed별 에피소드 JSONL.
- 상세 행동/도구 결과 trace는 조건별 첫 4개 사례(장애별 1개)만 저장한다.
  모든 에피소드의 정답/예측/비용/단계/실행시간은 저장한다.
- 기존 결과를 덮어쓰지 않는다. 출력 폴더가 있으면 실행을 중단한다.
- manifest, protocol, 데모 및 체크포인트 hash로 결과를 연결한다.

## 현재 측정하지 못하는 영역

정상 무장애 판정/false alarm, 다중 동시 장애, 시간에 따라 변하는 장애,
관측 누락·잡음·오래된 증거, 불완전한 명목 토폴로지, 실제 트래픽 처리량/굿풋,
실제 packet-level loss/jitter, MTTR/서비스 복구율, SLA 위반 시간, 에너지,
실장비/에뮬레이터 전이는 별도 실험이 필요하다.
현재 환경은 반드시 장애를 주입하며 복구 action이 없어 0%/0ms로 기록하지 않는다.

## 향후 LLM 및 다른 모델

동일한 관측과 pointer JSON 행동을 사용하는 **같은 정보 조건** 비교를 우선한다.
LLM에 원시 전체 텍스트 도구 결과/추가 traceroute를 제공하는 실험은 별도 조건으로 분리한다.
LLM의 모델 버전, prompt hash, 온도, 반복 seed, 토큰, 과금, 호출 지연, 타임아웃,
형식 오류 및 재시도 횟수를 함께 기록한다. API 오류 사례도 분모에서 임의 제외하지 않는다.
laya/jev의 정확한 모델 식별자는 사용자 확인 후 추가한다. 현재 실행 결과에 포함되지 않는다.
