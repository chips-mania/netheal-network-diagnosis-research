# LAYA 공식 환경 학습·평가 명세

작성일 2026-10-12 KST. 데이터 생성·본 학습·LAYA 공식 평가 전에 기록한다.

## 범위와 고정 조건

공식 Claude와 Jev 평가에 사용한 고정 green 소스와 원본 100개 스냅샷을 재사용한다. 모델이 공개 관측을 읽고 도구/인자를 선택해 진단하는 에이전트를 목표로 한다. 평가에서 증거를 미리 수집해 주거나 전문가 판단을 대신 넣지 않는다. 유료 API는 호출하지 않는다. 원본 Docker 대신 Windows 직접 FastMCP handler를 쓰는 차이는 Jev와 같다. 단일 6GB GPU여서 LAYA 에피소드는 동시성 1로 실행한다.

## 데이터와 교사

- 학습 40개: star/linear/mesh/hierarchical/random × 장비 8/12개 × 4개 장애 유형. seed 94010000–94010039.
- 개발 20개: 같은 5개 토폴로지 × 장비 10개 × 4유형. seed 94020000–94020019.
- 별도 공식 평가 100개: 기존 원본 고정 사례. 이미 Jev 결과를 본 사례이므로 프로젝트 전체의 미관측 평가라고 하지 않는다. LAYA 학습 및 checkpoint 선택에는 쓰지 않는다.
- 학습 교사는 scan → ID 순서 status 전체 → interfaces 전체 → scan의 공개 발견 행렬에서 확인한 무방향 연결마다 ping → 진단 순서의 고정 관측 수집 정책이다. 환경 내부의 숨겨진 링크 목록이나 장애 위치로 탐색을 정하지 않는다. 교사는 최적 탐색 전문가라고 주장하지 않는다.
- 학습에서 마지막 유형·위치 target은 시뮬레이터 정답을 사용한다. 정답은 target/평가 메타데이터에만 저장하고 state/질문/후보에는 넣지 않는다. 교사의 성공/실패로 사례를 선별하지 않는다.
- 원시 스냅샷·도구 결과·모든 질문 target을 보존한다. 학습/개발/공식 간 seed·snapshot ID·fingerprint와 공개 관측의 완전 일치 및 시간/단계 메타데이터를 제거한 중복을 검사한다. 중복이면 학습에 넣지 않고 제외 사유를 기록한다. 모델 점수에 따라 데이터를 다시 고르지 않는다.

## 입력과 학습

- 기본 checkpoint revision 7b928d828b7b0e022f929d9bd2e44165aa270148에서 새로 시작한다. 자원 점검에서 학습한 가중치를 이어 쓰지 않는다.
- 전체 Encoder+Head FP32, bitsandbytes 0.50.2 AdamW8bit, Encoder LR 2.5e-5/Head LR 1e-4, weight_decay 0.01, grad_clip 1, checkpointing 사용. microbatch 1/accumulation 1, seed 1012.
- 실제 optimizer update **2,048회**. tool/argument/fault_type/location 4범주를 순환하여 각 512회다. 각 범주의 질문을 seed 고정 셔플 후 순환한다. 단순 epoch로 예산을 대체하지 않는다. 이전 유형 전용 1,024회와 질문별 노출량이 다르다.
- cosine schedule 2,048 updates, min_lr=1e-6, soft cross entropy, 선택지 순서를 매번 섞는다. 최종 checkpoint만 사용하며 개발 정확도로 중간 checkpoint를 선택하지 않는다.
- 입력은 Jev v4와 같은 공개 전체 상태/도구 결과를 손실 없는 JSON 압축으로 표현한다. LAYA 공식 tokenizer로 max_len=4096/head_max_len=1024 안에 드는지 검사하며 잘림·후보 누락을 허용하지 않는다.
- 전체 상태가 안 들어가면 JSON 경로/값 조각으로 나누어 모든 원자료를 보존한다. 추론은 조각별 확률을 원자료 바이트 수로 가중 평균한다. 학습은 질문마다 고정 RNG로 조각 하나를 뽑아 해당 전체 상태의 target을 학습한다. 일부 조각만으로 정답이 불확실할 수 있는 약한 감독이며, 이 한계를 기록한다. 입력 잘림을 숨기거나 모든 증거를 한 번에 학습했다고 하지 않는다.
- 도구 후보는 원본 8개를 유지한다. 여러 인자를 갖는 행동과 edge 위치는 먼저 source, 그 예측 source에 유효한 나머지 인자를 묻는다. 진단 위치는 예측 장애 유형에 따라 분기한다. 후보는 공개 list_actions만으로 만들고 정답으로 줄이지 않는다.
- 디스크 여유 약 7.7GB를 확인했다. update 1024 복구 checkpoint와 최종 2048 checkpoint를 새 결과 폴더에 저장한다. 기존 실험 파일을 지우지 않는다.

## 개발 게이트와 공식 평가

학습을 끝내고 최종 checkpoint를 동결한 뒤 학습/개발의 고정 교사 관측에서 base와 학습 모델의 유형·예측 유형 기반 위치·공동 정확도를 구분해 측정한다. 원래 학습한 유형에 맞는 위치 target을 평가 때 정답 유형 분기로 사용하지 않는다. 선택지 canonical/reverse/rotate도 검사한다.

공식 전체 도구 탐색 게이트: 개발 공동 정확도가 base보다 최소 5%p 높고 학습 공동 정확도도 base보다 높아야 한다. 이는 작은 개발셋의 진행 기준이며 유의성/95% 정확도 달성을 뜻하지 않는다. 미달이면 판단 단계 실패를 보고하고 100개 전체 탐색을 무작정 실행하지 않는다는 기존 요청을 따른다.

통과하면 동결된 학습 모델로 공식 100개를 1회 평가한다. 모델이 직접 모든 도구를 선택한다. 환경 100단계, solver 100 turn, episode 1200초를 유지한다. 모든 오류/미완료를 분모에 포함하고, 진단 성공률·유형 정확도/macro-F1·위치 정확도·공식 장비 수 가중 지표·순서 민감도(개발)·도구 호출·모델 질문/조각 forward 수·시간/GPU/RAM을 기록한다. 공식 점수를 보고 설정을 바꾸지 않는다.
