# GPT-6.1 Sol와 Jev: 동일 과제에서 정확도·시간·과금 비교

작성: 2026-10-09. 상태: **API 연결·smoke 및 128회 pilot 완료·검증 통과. 본 평가 미실행**.
[설정 JSON](../../netheal-topology-generalization/config/api_comparison_v1.json)과 루트 [.env.example](../../.env.example)을 함께 사용한다.

## 연구 질문과 가설

같은 정보와 행동 기회를 주었을 때 GPT-6.1 Sol과 Jev의 장애 진단 정확도, 실제 사용금액, 진단 시간이 어떻게 다른가?
비용·시간은 **결과 변수**다. 동일한 금액을 소진시키거나, 빠른 모델을 기다리게 하거나, 결과 정확도를 비슷하게 튜닝하지 않는다.

주요 대비는 모두 GPT − Jev다. 방향을 미리 단정하지 않고 다음 세 차이를 양측 평가한다.

1. Exact(장애 유형과 위치 모두 정답) 차이.
2. 실패 사례까지 포함한 에피소드당 평균 과금 차이.
3. 실패 사례까지 포함한 에피소드당 평균 전체 진단 시간 차이.

세 주요 대비에는 Bonferroni 보정 98.33% bootstrap 구간을 사용한다. 0을 포함하면 차이 불확실로 판정한다.
단일 승자를 강제하지 않고 정확도·비용·시간의 절충을 보고한다. “동등한 정확도”는 유의차 없음만으로 주장하지 않는다.

## 모델과 고정 설정

| 항목 | GPT | Jev |
|---|---|---|
| 모델 | gpt-6.1-sol | jev-1.13.0 |
| API | OpenAI Responses | TypeSafe systemone |
| 추론 | medium | 해당 파라미터 없음 |
| 출력 | 완전한 합법 행동의 ID 하나, 구조화 출력 | 동일 후보에 대한 Choice |
| 출력 토큰 상한 | 8,192(추론 포함) | 제공자 방식에 따름 |
| 서비스 | Standard(default), 가속 모드 미사용 | 기본 서비스 |
| 보조 LLM | 없음 | 없음 |

GPT의 medium은 본 비교의 기본값이다. low/high 비교는 별도 실험으로 구분한다. temperature나 seed는 지원 확인 없이 보내지 않는다.
GPT 모델 페이지에는 날짜 snapshot이 명시되지 않아 가짜 snapshot 이름을 만들지 않는다. 요청·응답 model ID와 UTC 실행시각을 보존한다.
Jev는 움직이는 latest 대신 버전을 고정한다.

여기서 Jev 비교 대상은 **Jev 모델을 NetHeal 행동 선택에 연결한 정책**이다.
jev-ultrafast의 브라우저 탐색 속도 재현 실험은 아니다. 네트워크 행동은 닫힌 후보 집합이므로 TYPE_TEXT용 보조 모델이 필요 없다.
완전한 행동 후보 하나를 고르는 방식을 양쪽에 적용한다. Jev의 여러 질문 병렬 분해는 이후 별도 ablation이며 본 비교에 섞지 않는다.

## 동일하게 맞추는 조건

- v3와 같은 8개 토폴로지·크기 조건, 단일 장애 네 유형 균등 분포. 정상·복합 장애는 이번 범위 밖.
- 동일한 물리적 사례, 정답, 시작 상태, 도구 의미, 이름 변경 매핑. 관측 난수는 사례·행동 의미별로 결합해 실행 순서 차이가 결과를 바꾸지 않게 한다.
- 공개 관측 그래프, 명목 인벤토리, 특징 정의, 영어 설명, 합법 행동 후보를 공유한다. 숨은 상태·정답·Rule 추천을 입력하지 않는다.
- 양쪽 모두 현재 공개 그래프만 받고 사적 대화 이력은 누적하지 않는다. 진단 설명 생성, 웹 검색, RAG, few-shot, 학습은 사용하지 않는다.
- 최대 40번 행동 선택. 하나의 선택은 하나의 도구 실행 또는 최종 진단이다. 모든 합법 후보를 포함하고 정답 기반 후보 축소는 하지 않는다.
- 공통 텍스트를 가능한 그대로 공유하되 API schema 포장 차이는 허용하고 해시·바이트·토큰 수를 기록한다. 서로 다른 tokenizer의 토큰 수를 같게 만들지 않는다.
- 입력 길이는 pilot에서 두 API 모두 수용 가능한지 확인한다. 조용한 truncation은 금지하고 넘치면 설계를 수정한 뒤 다시 고정한다.
- 동일 클라이언트·네트워크, 동시 실행 1, 사례별 GPT/Jev 순서를 무작위 AB/BA로 배정. 제공자 서버 위치 차이는 관측되는 API 서비스 특성이다.
- 연결 재사용을 동일하게 허용하고 초기화 시간과 첫 요청을 별도 기록한다. 애플리케이션 응답 캐시는 끈다. 제공자 자동 캐시는 usage로 기록하며 강제 비활성화됐다고 가정하지 않는다.

행동 경로가 달라지면 이후 관측과 호출 수도 달라진다. 이는 정책 성능의 일부다.
별도의 동일 관측 replay는 요청 단위 속도 분석에 쓸 수 있지만, 실제 순차 진단 성능을 대체하지 않는다.

## 실행 규모와 중단 규칙

Pilot은 8조건 × 8사례 = 64개(조건당 장애별 2개), 원래 이름, 1회, 모델 2개로 **128 에피소드**다.
프롬프트·길이 제한·과금 파서·API 오류·실행 시간을 점검하고 사례당 예상 비용을 산출한다.

본 평가는 새 seed의 8조건 × 100사례 = **800개 독립 사례**, 이름 2조건 × 3회 반복 × 2모델 = **9,600 에피소드**다.
seed 영역은 pilot 9,100,000대, 본 평가 9,200,000대로 예약하고 기존 실행과 실제 교집합이 없는지 실행 전에 검증한다.
같은 사례의 이름 변형과 반복은 독립 표본이 아니다. 조건별로 물리적 사례를 cluster로 재표집(10,000회)해 모든 짝을 보존한다.
검정력은 보장하지 않으며 pilot 이후 규모 변경은 본 평가 전 설계 개정으로 남긴다.

요청 timeout 120초, 에피소드 watchdog 600초, 동시 실행 1.
이는 동일 비용·시간 맞추기가 아닌 공통 실행 한도다. watchdog 결과는 검열된 종료이며 제한 없는 해결 시간으로 해석하지 않는다.
SDK의 숨은 자동 재시도를 끄고 전송 실패·429·5xx 등에 최대 1회 명시적 재시도한다. 대기와 재시도도 시간·비용에 포함한다.
Retry-After를 존중하고 남은 watchdog 시간보다 길면 종료한다. 형식 오류·잘못된 행동은 별도 실패로 종료하며 공짜 교정 호출을 하지 않는다.

사례별 금액 상한은 두지 않는다. 전체 지출 중단 장치는 별도로 설정할 수 있으나 중단 시 부분 실행으로 보고한다.
금액 한도로 끝난 불완전 사례를 제거한 결과만 본 평가 완료라고 주장하지 않는다.
API 자격증명 오류는 실행 중단 원인으로, 일시적 서비스 오류는 계획된 사례의 운영 실패로 구분한다.

## 측정 지표

| 영역 | 지표와 해석 |
|---|---|
| 정확도 | Exact, 유형 정확도, 위치 정확도, 장애별 recall/F1 및 macro-F1, 혼동행렬. 미완료도 전체 Exact 분모에 포함 |
| 실패 | 오진, 40단계 초과, watchdog, API 실패, 출력 형식/후보 오류를 구분. 미진단은 각 실제 유형의 FN에 포함 |
| 시간 | 요청 p50/p95, 에피소드 평균/p50/p95, API 대기·backoff·도구 실행·직렬화 시간. 성공 사례만의 시간도 보조 보고 |
| 과금 | 전체 및 사례당 평균/p50/p95 USD, 총비용/정답 수, 실패에 사용된 금액. 정답 0이면 정답당 비용은 정의 불가 |
| 사용량 | 입력·캐시 읽기/쓰기·출력·추론 토큰, API 요청/재시도 수. 추론 토큰을 출력 요금에 이중 가산하지 않음 |
| 도구 효율 | 호출 수, 동일 도구·인자 반복 비율, 가중 도구 비용, 정답까지 단계 수. 도구 가중 비용은 API 달러와 별개 |
| 안정성 | 3회 반복의 정답률 변동·최종 진단 일치율, 이름 변경 전후 격차 |
| 일반화 | 토폴로지·크기·장애 유형별 모든 위 지표. 전체 평균만으로 실패 조건을 숨기지 않음 |

Jev의 confidence와 GPT의 자기보고 확신은 같은 확률 척도가 아니므로 직접 calibration 우열을 주장하지 않는다.
네트워크 공통 ping/지연/손실 지표는 사례 특성으로 연결하되 모델이 네트워크 품질을 개선했다는 결과로 해석하지 않는다.
탐지 지연·정상 오경보·MTTR·실제 throughput은 이번 진단 전용 실험에서 측정하지 않는다.

## 과금 계산과 기록

2026-10-09 공식 문서 기준, USD/100만 토큰:
GPT 입력 2.00, 캐시 입력 0.10, 캐시 쓰기 2.50, 출력 10.00.
Jev 입력 0.042, 출력 무료. 실제 적용 가격과 계정 조건은 실행 시 다시 확인한다.

예를 들어 캐시 없이 입력 3,000/출력 200토큰을 10회 쓴다면 GPT 계산 비용은 0.08달러다.
Jev에서 실제 청구 입력이 요청당 3,000토큰으로 10회라면 0.00126달러다.
이는 **동일 토큰 가정의 계산 예시**이며 두 정책의 실제 호출 수·토큰량·정확도를 예측한 값이 아니다.

제공자가 반환한 usage를 기준으로 과금 추정치를 만들고 계정 사용내역과 대조한다.
캐시 쓰기/읽기 항목을 중복 합산하지 않는다. 미확인 요금·실패 요청 사용량은 0이 아니라 unknown으로 남긴다.
청구 자료 확인 전에는 “실제 청구 확정액” 대신 “usage 기반 추정액”이라고 표시한다.
무료 크레딧·할인은 서비스 원가 비교와 별도로 보고한다. 환율·세금도 USD 기본 비교와 분리한다.

사례/반복/모델 ID, prompt/schema/config/source 해시, 요청 ID, 응답 모델, UTC 시각, 모든 요청의 usage,
종료 이유, 도구 trace, 정답·예측, 지연 및 오류를 저장한다. 인증 헤더와 API 키는 로그·manifest에 넣지 않는다.
본 평가에 들어가기 전에 설정과 프롬프트를 고정하고 결과를 본 뒤 변경하지 않는다.

## .env 사용과 구현 상태

프로젝트 루트의 `.env`에 `OPENAI_API_KEY`, `TYPESAFE_API_KEY`를 입력한다.
`.env`는 기존 Git ignore 규칙으로 제외되고, 빈 키를 가진 `.env.example`만 공유한다.
일반 파라미터는 JSON 한 곳에 두어 env와의 중복 설정 충돌을 피한다.

**실행기 `src.run_api_comparison`을 구현했다. 현재 smoke/pilot만 지원하며 본 평가 실행은 별도 단계다.**
키를 넣는 것만으로 호출되거나 비용이 발생하지 않는다. 아래 명령을 실행하면 유료 API를 호출한다.
두 provider 연결, 공통 행동 후보, usage 기반 비용, 요청 timeout/에피소드 watchdog, 명시적 재시도, 요청·행동 로그를 구현했다. 전체 지출 guard는 에피소드 사이에서 확인하므로 한 에피소드의 초과분이 발생할 수 있다.
v2/v3 실행 시점 소스와 결과는 수정하지 않는다.

## 현재 실행 명령

프로젝트 루트에서 가상환경 Python으로 실행한다. 출력 폴더는 새 이름을 사용한다.

```powershell
$env:PYTHONPATH = (Resolve-Path ./netheal-ai-agent-benchmark).Path
cd netheal-topology-generalization
python -m pip install -r requirements-api.txt
python -m pytest tests/test_api_comparison.py -q
python -m src.preflight_api_comparison
python -m src.run_api_comparison --phase pilot --out results/api_pilot_new
python -m src.report_api_comparison results/api_pilot_new
```

API 연결 점검은 모델당 1회 호출하며 본 평가에서 제외한다. 현재 실행은 `.runtime/venv`를 사용했다.
`manifest.json`의 completed와 보고서의 verification passed를 함께 확인해야 한다.
요청 단위 JSONL은 매 호출 직후, 에피소드 JSONL은 종료 직후 저장한다. 자동 재개는 아직 지원하지 않는다.
