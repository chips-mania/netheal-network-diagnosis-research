# LAYA 기본 모델 — 공식 100개 에이전트 평가 수정 계획

작성일: 2026-10-12 KST. 사용자 정정에 따른 현재 우선 계획이다.
상태: 계획 수정 완료. LAYA 공식 100개 평가 및 학습은 아직 실행하지 않았다.

## 목표와 범위

Jev v4와 공개 Claude Sonnet 4.5 평가에 사용한 **동일한 공식 100개 초기 스냅샷**으로, 기본 LAYA 체크포인트의 전체 에이전트 성능을 먼저 측정한다. LAYA가 도구 탐색부터 최종 장애 유형·위치 제출까지 직접 선택한다.

이전 응답에서 제안한 train 40 / development 20 고정 관측 평가는 이번 베이스라인 대상이 아니다. 해당 자료는 추후 학습·개발 평가 후보로만 보존한다. 기본 모델은 프로젝트 내 추가 학습 전 체크포인트를 뜻하며, 자원 시험이나 이전 학습 실험 가중치를 사용하지 않는다.

이번 순서는 기존 공통 입출력 인계 문서의 '진단 학습 개선 후 전체 에이전트 평가'보다 우선한다. 먼저 공식 100개 baseline을 측정하고, 이후 별도 학습 실험을 설계한다.

## 1. 기존 평가 조건 재확인

- 원본 환경·도구·채점 소스와 공식 스냅샷: `netheal-topology-generalization/results/netheal_official_jev_20261011_v1/upstream/`.
- 비교 결과: `runs/official_benchmark/jev/netheal_official_jev_20261011_v4/` 및 저장된 Claude 원본 결과. 재집계하여 snapshot ID, seed, fingerprint 100개 대응과 가중치 정의를 검증한다.
- 초기 힌트와 공개 과제, 도구 스키마, 행동 공간, 환경 100단계 / solver 100 turn / 에피소드 1200초 제한을 유지한다. 원본 코드의 단계 소모 및 종료 규칙을 따른다.
- Windows 직접 handler·FP32 로컬 GPU·동시성 1을 명시한다. 실행 환경과 병렬도 차이가 있으므로 시간 성능은 모델 자체 속도로 단정하지 않는다.

## 2. LAYA 전체 에이전트 어댑터 구현

새 소스와 별도 실행 폴더를 사용하고 동결 Jev v4 코드는 변경하지 않는다.

1. 각 solver turn에서 공개 과제·힌트·이전 공개 도구 이력으로 다음 도구를 선택한다.
2. Jev v4와 동일한 공개 후보 생성 및 순서를 사용한다. 일반 도구 인자 후보가 255개를 넘는 경우에만 source 선택으로 나눈다.
3. `submit_diagnosis`는 유형을 먼저 예측하고 **그 예측 유형**의 위치 후보를 직접 선택한다. 링크도 직접 선택하며 정답 유형·정답 위치를 공급하지 않는다.
4. 선택한 도구를 원본 환경에서 실행하고 공개 응답만 다음 입력에 추가한다. 고정 정책으로 증거를 미리 모아 주거나 기존 Jev/Claude의 행동 궤적을 대신 수행하지 않는다.
5. 후보·관측 절단이나 정답 기반 요약 없이 문맥 한도를 검사한다. Jev v4 압축·이력/트리 분할을 출발점으로 LAYA 토큰 한도를 추가 확인한다. 필요한 추가 분할, envelope, 결합 가중치, 단일/다중 조각 선택 규칙과 온도 보정 적용 여부를 개발 검증에서 확정하고 본 평가 전에 동결한다.

공식 사례가 같다는 것과 모델 입력 문자열까지 동일하다는 것은 구분한다. 모델의 도구 선택이 달라지면 이후 관측도 달라진다. LAYA 한도 때문에 Jev v4와 분할이 달라지는 부분을 기록하며, 결과는 동일 사례의 **에이전트 비교**로 보고한다. 새 공통 입력으로 Jev까지 재측정하는 엄밀한 통제 비교는 별도 후속 실험이다.

## 3. 본 평가 전 검증과 동결

- 모의 모델 응답으로 모든 도구·인자 분기, 후보 순서, 예측 유형에 따른 위치 선택, 종료·시간·단계 제한을 검증한다.
- 공개 입력만 사용하는지, 압축/분할 후 복원이 정확한지, LAYA 토큰 절단·선택지 손실이 없는지 확인한다.
- 공식 100개와 분리된 개발 사례로 실제 LAYA smoke 및 긴 입력 추론 메모리 점검을 수행한다. 학습/backward/optimizer 시험은 baseline의 선행 조건이 아니다.
- 1200초 제한에 준비·분할·forward 시간을 포함한다. 제한 내 완료하지 못하면 시간 초과로 기록하며 성능을 보고 예산을 늘리지 않는다.
- 모델/토크나이저/설치 소스/평가 소스/명세 해시, 길이·보정·seed·분할·재시도·복구 규칙을 동결한다. 결정적 입력 오류와 OOM은 동일 설정 자동 반복으로 숨기지 않는다.

## 4. 공식 100개 평가 실행

- 기본 체크포인트: `.runtime/huggingface/hub/models--convaiinnovations--laya/snapshots/7b928d828b7b0e022f929d9bd2e44165aa270148`.
- 추가 학습 updates=0, FP32, GPU 작업 하나씩 실행한다.
- 예정 실행 경로: `runs/official_benchmark/laya/2026-10-12_official_baseline_r01/`. 실제 시작일이 달라지면 날짜를 조정한다.
- 사례별 입력·선택 확률·판단·도구/인자·공개 응답·종료 상태·채점·시간·자원 사용량을 저장한다. 환경 단계, 판단 질문, 조각 forward 수를 구분한다.
- 완료 사례를 보존하여 재개한다. 중단 시도는 별도 보존하고 최종 분모에 중복 계산하지 않는다. 정답률에 따른 재시도나 설정 변경은 하지 않는다.
- Jev·Claude 추가 API 호출, 학습, 외부 리더보드 제출은 이번 실행에 포함하지 않는다.

## 5. 결과 집계와 이후 학습

원본 evaluator로 전체 100개를 집계하며 오류·시간 초과도 분모에 포함한다. 공동 성공 사례 수, 공식 장비 수 가중 성공률, 유형 정확도/macro-F1, 위치 정확도, 오진·미완료·오류, 단계·질문·forward 수와 자원을 보고한다. 사례별 Jev/Claude 결과를 연결해 동일 사례 비교표를 만든다.

기존 보고서의 비교 기준은 Jev v4 **42/100, 공식 가중 성공률 35.59%**, Claude **66/100, 공식 가중 성공률 65.04%**다. 재집계로 확인하며 단순 성공률과 가중 성공률을 섞지 않는다. 이미 프로젝트에서 분석한 100개이므로 새 미관측 테스트셋이라고 부르지 않는다.

Baseline 완료 후 별도 데이터로 학습량 비교를 설계한다. 기존 40/20 자료의 재사용 여부·입출력 계약·라벨·학습 예산·checkpoint 선택 규칙을 그때 확정한다. 공식 100개를 학습 데이터나 반복적인 checkpoint 선택용으로 사용하지 않는다.

## 잘못 시작한 40/20 작업의 처리

`common_io_baseline.py`와 `common_diagnosis_io.py`, 관련 명세·테스트 초안은 보존하되 이번 공식 에이전트 실행기로 사용하지 않는다. 기존 실행 폴더에는 config와 데이터 감사 파일만 확인됐으며, 모델 예측 및 사례별 평가 결과 파일은 없었다. 해당 실행은 `superseded_before_model_evaluation`로 기록한다.
