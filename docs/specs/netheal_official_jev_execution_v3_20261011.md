# Jev 문맥 한도 수정 및 재측정 사전 명세

작성일: 2026-10-11 KST. 본 평가 시작 전에 소스와 이 문서의 SHA-256을 frozen_protocol.json에 고정한다.

## 목적과 고정 조건

v2의 100개 중 39개가 HTTP 400 max_tokens_exceeded로 미완료됐다. 관측을 삭제하지 않는 입력 표현 수정으로 문맥 실패가 줄어드는지, 전체 진단 성공률이 어떻게 달라지는지 측정한다. 성공률 개선은 미리 가정하지 않는다.

기존 공식 Claude 실행의 동일한 100개 스냅샷, 고정 green 이미지에서 추출한 환경·도구·채점 소스, 공개 heuristic hint, 최대 환경 100단계, solver 100 turn, 에피소드 1,200초, 동시 에피소드 5, Jev 1.13.0을 유지한다. 요청 시작 간격은 최소 0.5초다. 원본과 fingerprint가 100/100 일치한다. 전체 Docker 실행이 아니라 Windows Python 3.13.2에서 원본 FastMCP handler를 직접 호출한다. 외부 Claude 수치와의 비교는 이러한 어댑터·실행 환경 차이를 포함한다.

## 입력 처리 규칙

1. 실제 선택한 모든 도구 결과와 시간 순서를 유지한다. 자동 list_actions는 인자 후보 생성용이며 v2와 동일하게 전체 결과를 모델 이력에 자동 추가하지 않는다.
2. 최신 공개 상태를 한 번 저장하고, 과거 공개 상태는 역방향 차이로 저장한다. 도구별 action_result는 사건별로 보존한다. 반복 하위 자료는 참조, 연속 정수는 범위, 반복 배열은 값과 횟수, 같은 열의 객체 배열은 열 이름과 행으로 표시한다. 숫자를 반올림하지 않는다.
3. 각 요청 직전에 디코딩하여 원래 JSON과 정확히 같은지 검사한다. 정수/실수 자료형과 배열 순서도 보존한다. JSON 객체 키 순서는 비교에서 무시한다. 읽는 법을 함께 제공하고 압축 자료를 문자열로 전달한다. 정보 보존은 모델이 이 표현을 같은 수준으로 이해한다는 보장은 아니다.
4. 압축 state UTF-8 바이트 + 질문 JSON UTF-8 바이트 + 여유 512가 24,000 이하이면 단일 요청으로 평가한다. 바이트는 제공사 토큰 수의 정확한 대체값이 아니며, 보수적인 요청 가드다.
5. 이를 넘으면 이력을 연속된 묶음으로 나눈다. 모든 사건을 빠짐없이 포함하고, 공통 과제·힌트·도구 설명과 최신 공개 결과를 각 묶음에 반복한다. 각 묶음에는 동일 선택지를 묻는다. 묶음별 반환 확률을 사건 수로 가중 평균하여 최대값을 선택한다. 동률은 원래 첫 번째 선택지다. 단일 묶음에서는 제공사가 반환한 choice를 그대로 따른다. 추가 호출과 결합 결과를 별도 기록한다.
6. 단일 사건도 한도에 들어가지 않으면 ContextBudgetError로 남긴다. 관측 삭제나 진단 정답 기반 축약은 하지 않는다. 여러 묶음의 확률 결합은 전체 증거를 동시에 읽는 방식과 다르며, 관계 추론 손실 가능성이 있다.
7. 유형을 먼저 예측하고 해당 예측 유형의 위치 선택지를 묻는다. 정답 유형을 선택지 구성에 쓰지 않는다. 정답·비공개 장애 상태·전문가 진단·유료 생성형 요약 모델을 입력에 넣지 않는다.

## 실행 전 검증과 판정

- 기존 v2 본 평가 요청 1,571개의 압축·복원이 정확히 일치하는지 확인한다. 숫자와 시간 변화 예외도 검사한다.
- 이전 39개 오류 입력은 초기 압축 표현으로 모두 HTTP 200을 받았다. 예측 정답률은 설정 선택에 사용하지 않았다.
- 개발 100단계 이력은 압축만으로는 여전히 400을 받아 분할을 추가했다. 최종 분할 개발 확인은 8개 요청 모두 수용됐다. 이 과정의 실패 요청과 비용도 보존한다.
- 개발 smoke 3 turn은 HTTP 200 요청 5회로 끝났다. 성능 평가가 아니다.
- 본 평가의 100개를 모두 새 디렉터리에서 실행한다. 39개만 골라 전체 성능으로 보고하지 않는다. 평가 중 성공률을 보고 설정을 바꾸지 않는다.
- 주된 기술 판정: 전체 100개에서 max_tokens_exceeded와 로컬 ContextBudgetError 발생 건수. 0개면 이 고정 평가에서 입력 한도 문제를 해소한 것으로 판정한다. 모든 미래 입력에 대한 보장은 아니다.
- 성능: 전체 100개를 분모로 성공·오진·미완료를 구분하고, 공식 장비 수 가중 성공률/위치 정확도, 단순 유형·위치 정확도, 유형 macro-F1, 유형별 결과, v2 및 Claude와 사례별 비교를 기록한다. 요청 수·분할 수·토큰·추정 비용·실행 시간도 기록한다.
- 일시적 네트워크/서버 실패에는 기존 최대 10회 에피소드 재시도 정책을 유지한다. 결정적 입력 오류나 오답을 재시도하지 않는다.
- 이미 사용한 평가셋을 통한 연결 수정 후 재측정이다. 독립 미관측 평가나 모델 자체의 추론 능력만의 차이라고 주장하지 않는다.
