# LAYA 공개 관측 표현 비교 사전 계획

2026-10-10. 데이터 생성·모델 학습·새 평가 점수 확인 전에 고정한다.

- 목적: 시뮬레이터의 실제 공개 도구 관측을 충분히 수집한 후 장애 유형과 위치를 판단하는지 검증한다. 합성 정답 신호, 실장비 검증, LAYA 도구 탐색 평가는 아니다.
- 데이터: Star/Linear 각 4노드, 단일 장애 4종, 심각도 배수 10–20. 각 topology×fault 셀에서 학습 4개(총32), 새 평가 8개(총64). 학습 seed는 91000000+topology_index×100000+fault_index×10000+attempt, 평가는 92000000에서 같은 산식. 셀별 최대 1000회 시도. 성공 여부로 선별하지 않는다.
- 관측: scan 1회 → ID 정렬한 모든 장치 status → 모든 장치 interfaces → 정렬한 모든 명목 방향 링크 ping. 40회 예산 내 고정 수집이며 정답에 따라 도구를 고르거나 조기 종료하지 않는다. PublicView와 공개 도구 결과만 사용한다. 원시 도구 기록과 전체 공개 GraphObs를 저장한다.
- 표현: 동일한 GraphObs의 전체 필드를 5자리 유효숫자로 양자화해 숫자 표/영문 자연어 문장으로 각각 표현한다. 필드명, 값, 장치/링크 순서는 동일하다. 전문가 결론, 정답, seed/사례 ID는 입력하지 않는다. 역변환한 필드/값의 완전 일치를 검사한다. 이 검사는 선택한 그래프 표현 간 동등성으로, 원시 도구 정보 전체의 무손실 압축을 의미하지 않는다.
- 중복: 에피소드 seed와 전체 관측, step_fraction을 제외한 관측 핵심의 해시를 검사한다. 기존 LAYA train/calibration/validation의 모든 관측과 새 학습·평가 사이 중복을 제외하며, 동일 분할 내 중복도 제외한다. 제외 원인과 후보 기록을 보존한다. 연속 지연값만 다른 유사 사례는 정확 중복이 아니며 그 한계를 보고한다.
- 전문가: 동일한 고정 수집 관측의 RuleAgentV2 결론과 성공을 별도 audit에 기록한다. 성공 사례만 고르지 않는다. 그래프 표현의 충분성은 전문가 원시 메모리 성공만으로 보증하지 않는다.
- 학습: 공개 기본 checkpoint에서 시작, FP32, 마지막 Encoder 블록+Head, AdamW, Encoder LR 2.5e-5/Head LR 1e-4, soft-CE, microbatch=1, accumulation=1, 선택지 섞기, seed 41/52/63. 표/문장 6실행을 GPU 한 개에서 순차 수행한다. 전체 Encoder 학습은 아니다.
- 예산: 사례당 유형 질문 1개와 정답 종류의 위치 질문 1개, 총64질문×16epochs=1024 실제 optimizer updates. 유형/위치 각512 updates. 이전 유형 전용1024 updates와 과제별 노출이 다름을 명시한다. cosine schedule은1024 updates에 맞춘다. 최종 가중치만 평가하고 중간 평가/최적 checkpoint 선별은 하지 않는다.
- 입력 예산: max_len=4096/head_max_len=1024. 공식 tokenizer로 잘림과 후보 누락/병합을 검사하고 실패 시 중단한다. 점수에 따라 길이·데이터·학습 설정을 변경하지 않는다.
- 평가 개방: 여섯 학습 실행을 모두 완료하고 가중치 해시를 고정한 뒤 새 평가를 연다. 기본 모델도 동일한 두 표현에서 평가한다. 학습 사례 암기 점수와 새 평가 점수를 별도 보고한다.
- 주 평가: 유형 argmax에 따라 node/edge 질문을 선택한다. 유형 정확도·4종 macro-F1, 위치 정확도, 유형+위치 Exact를 기록한다. 링크 역방향은 기존 strict_location 기준으로 동등하다. 정답 유형 분기의 위치 점수는 oracle 보조 평가로만 표시한다.
- 순서: 유형 24개 전순열과 위치 후보의 canonical/reverse/1칸 회전을 사전 지정한다. 유형 순서 평가는 canonical 위치를, 위치 순서 평가는 canonical 유형을 고정한다. 순서별 정확도·Exact·의미상 예측 변경률을 기록한다. 반복 질문 수를 독립 사례 수로 계산하지 않는다.
- 판정: 암기 통과는 학습 유형 정확도와 Exact 모두95% 이상. 새 관측 판단 통과는 새 평가 유형 정확도·macro-F1·위치·Exact 모두95% 이상이며 모든 유형 순서와 세 위치 순서의 Exact도95% 이상. 각 seed별 판정, 3/3 여부를 보고한다. 표현 차이는 동일 사례 paired 차이와 사례 단위 bootstrap 95% 구간(seed 평균, 2000회, seed731)으로 기술하며 사후 우승 설정을 새 평가에 재학습하지 않는다.
- 자원: 학습/평가 wall time, PyTorch peak allocated/reserved, nvidia-smi GPU utilization/전체 GPU memory를 기록한다. 전력 비용 미측정/API 호출0. 저장 마지막 블록+Head를 기본 모델에 다시 적용해 canonical logits 오차<1e-4를 검사한다.
- 부정 결과: 이 예산·데이터·표현에서 충분한 성능이라는 가설만 기각할 수 있다. 모델 고유 한계, 전체 미세조정 효과, 더 많은 학습 사례/updates, 크기·토폴로지 외삽, 정상/복합 장애, 실장비 성능은 판단하지 않는다. 개선 확인 전 전체 도구 탐색을 재실행하지 않는다.

실행 코드는 `scripts/laya_observation_data.py`, `scripts/laya_observation_controls.py`에 추가하고 별도 `results/laya_observation_controls_v1/`에 계획·소스·데이터·가중치·평가를 저장한다. 기술 오류 수정은 원인과 시점을 기록하고 평가 점수에 따른 설정 변경과 구분한다.
