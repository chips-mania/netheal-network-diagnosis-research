중첩 계측은 하위 시간 중복을 제외했다. 합계와 전체 시간 차이는 약 6마이크로초다. 환경 도구는 실제 네트워크 원격 명령이 아닌 NetHeal 시뮬레이터 도구다. Python 시작, 모듈 import, 스냅샷 파일 로딩은 에피소드 계측 전에 수행했으므로 위 시간에 포함되지 않는다. 요청별 기존 seconds 필드는 요청 시작 로그 기록까지 포함하므로 순수 HTTP 래퍼 합계와 약간 다르다.

압축·복원은 28회 판단에 56회 실행됐다. 분할 필요 여부 검사에서 한 번, 실제 요청 생성에서 한 번 수행하는 기존 코드 경로 때문이다. 결과 재사용으로 중복 계산을 줄이는 것은 다음 최적화 후보이며 이번에는 적용하지 않았다.

입력 토큰 145,208개. 공식 입력 100만 토큰당 $0.042, 출력 무료 기준 예상 API 비용은 $0.006098736이다. 청구 확정액이나 로컬 연산 비용을 포함한 값은 아니다.

## 기존 실행과의 비교 및 한계

과거 동일 사례는 55.51초, 22회 API, 11단계였다. 그 실행의 API 응답 기록 합계는 4.6630초(8.40%)였다. 과거에는 5개 사례가 전역 0.5초 요청 간격을 공유했다. 해당 사례 첫~마지막 요청 사이 전체 106회 호출이 있었고 전체 평균 시작 간격 0.5092초, 해당 사례 평균 간격 2.5461초였다.

이번에는 판단 경로도 달라졌으므로 55.51초와 8.51초 차이를 전부 대기 제거의 인과 효과로 단정하지 않는다. 다만 단독 실행에서 도구 시간이 약 0.027초에 불과하며, 오래 걸리는 시뮬레이터 도구가 기존 지연의 주원인이었다는 설명을 지지하지 않는다. 과거 대기·전처리의 정확한 세부 비중은 당시 별도 계측이 없어 복원할 수 없다.

공식 문서 확인: https://docs.typesafe.ai/models — 2026-10-13 기준 초당 80회·입력 100K 토큰 제한. 제한은 변경 가능하다. 이번 실행에서는 고정 대기를 없애되 단일 순차 요청만 보냈으며 오류 시 에피소드가 중단되는 기존 처리 방식을 유지했다.
