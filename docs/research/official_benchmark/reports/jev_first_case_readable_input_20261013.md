# Jev 첫 사례 입력 표현 비교 — 2026-10-13

첫 사례의 기록된 관측을 고정하고 실제 Jev API를 재호출했다. 기존 압축 입력과 일반 JSON 입력 모두 최종 유형 `link_failure`, 위치 `center->edge_5`를 선택했다. 일반 JSON 방식에서 속도나 정확도 개선은 확인되지 않았다.

## 범위와 방법

- 사례: `00bd290a-df64-46a6-8f06-f087bde022a9`.
- 기존 실행의 22개 판단 시점에 대해 두 입력을 각각 평가했다. 모델, 질문과 선택지는 유지했다.
- 변경 입력은 압축 상태를 일반 JSON으로 복원하고 도구 정의를 이름·설명·입력 스키마로 간소화했다. 관측 이력은 유지했다. Claude 시스템 프롬프트 전체를 적용한 실험은 아니다.
- 변경 입력 중 11개가 기존 24KB 가드를 넘어 이력을 시간순으로 분할했다. 각 조각의 선택 확률을 이력 항목 수로 가중 평균했다. 따라서 표현 변경 외에 분할·집계 방식의 영향도 포함된다.
- 판단마다 기존/변경 호출 순서를 교대했다. 각 조건 1회이며 재시도는 없었다.

56개 호출 모두 HTTP 200이었다. HTTP 시간은 네트워크 왕복을 포함하며 호출 사이 대기와 환경 도구 실행은 제외한다. 전체 사례 실행시간으로 해석하면 안 된다.

두 방식의 선택은 22개 중 13개가 같았다. 기존 입력 재호출도 과거 응답과는 19개만 같았으므로, 선택 변화 전부를 입력 표현의 효과로 단정할 수 없다.

## 해석과 한계

이 사례에서는 압축을 풀어 누적 관측을 전달하면 입력 토큰이 약 3.80배, HTTP 시간 합계가 약 1.79배로 늘었다. 첫 입력은 작아졌지만 후반 누적 이력이 커지고 분할 호출이 추가되었다.

새 선택으로 실제 도구를 실행하지 않았으며, 다음 판단에는 계속 과거 실행의 관측과 선택지를 넣었다. 따라서 두 방식이 자율 탐색에서도 모두 성공한다거나 성공률이 개선됐다고 말할 수 없다. 또한 개별 분할 호출은 전체 증거를 한 번에 보지 않으므로 전체 JSON을 단일 호출에 제공한 실험과도 다르다.

다음 개선 후보는 누적 스냅샷의 중복을 줄이고 현재 상태와 필요한 관측 이력을 명시적으로 구성하는 것이다. 정보 보존 여부와 실제 자율 탐색 결과를 별도로 검증해야 한다.
