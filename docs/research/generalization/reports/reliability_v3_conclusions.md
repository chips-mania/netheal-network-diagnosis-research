# v3: 가설을 고정한 네트워크 장애 진단 실험 결론

문서 정리·검증일: 2026-10-09. 실행 식별자는 `factorial_v3_20261008`로 보존한다.
LAYA, Jev, 일반 LLM은 이번 비교에 포함하지 않았다.

**머신러닝으로 시뮬레이터의 단일 장애 유형과 위치를 찾는 것은 가능하다. 그러나 새로운 구조·크기에 안정적으로 일반화하거나 Rule을 대체할 수준이라는 근거는 없다.**
이번에는 v2에서 발견한 문제를 출발점으로 가설과 판정 기준을 실행 전에 고정하고, ID 의존성과 학습 구조 다양화의 효과를 검증했다. 모든 연구 공백을 채운 실험이라는 뜻은 아니다.

## 무엇을 통제했나

순위 처리(original / 순위 특징 제거 / 일관된 ID·순서 변경 증강) × 학습 구조(Star / Star+Linear)의 3×2 설계다.
각 조합을 3개 replica(41, 52, 63)로 학습해 총 18개 모델을 만들었다.
모델 구조, 모델당 전문가 데모 2,112개, 6,000 optimizer update, 배치 64, 학습률, 최대 40단계 평가 예산을 고정했다.
데모의 에피소드 수는 같지만 궤적 길이가 달라 transition 수까지 같은 것은 아니다.

Star 6/10/12, Linear 6, Mesh 6/10, Random 6/10의 8조건에서 각각 100개, 총 800개 독립 사례를 사용했다.
각 사례는 네 장애 유형을 균등하게 포함한다. 같은 물리적 사례를 원래 이름과 변경된 이름으로 평가했고, 모든 모델의 학습을 끝낸 뒤 최종 평가를 시작했다.
18×800×2와 Rule 800회를 합쳐 **29,600회 평가**를 완료했다. 반복 평가를 29,600개의 독립 장애 사례로 해석하지 않는다.

ID 변경은 정책이 보는 공개 그래프의 ID·순서와 행동 매핑에 적용했다. 시뮬레이터 내부 ID까지 변경한 것은 아니며, Rule은 원래 이름 조건의 정보 충분성 기준이다.
숨은 장애 상태는 정책 입력에서 차단했다.

## 가설과 판정

Exact는 장애 **유형과 위치를 모두 맞힌 비율**이다. 아래 효과의 단위는 퍼센트포인트(%p)다.

| 가설 | 사전에 정한 주요 비교 | 결과 | 판단 |
|---|---|---|---|
| H1: ID·순서 증강은 이름 변경에 대한 진단 성능을 높인다 | 변경된 이름 조건에서 augmented − original; 두 학습 구조와 전체 평가 조건 평균 | **+11.1%p**, 97.5% CI **[+6.2, +16.1]** | 이 실험 범위에서 지지 |
| H2: 학습 구조 다양화는 미학습 구조로의 전이를 높인다 | Mesh·Random 6/10에서 mixed − star; 세 순위 처리와 두 이름 조건 평균 | **+15.8%p**, 97.5% CI **[+11.3, +21.2]** | 이 실험 범위에서 지지 |
| H3: 두 개입을 함께 쓰면 추가 상호작용이 생긴다 | 증강 효과의 학습 구조 간 차이; 탐색 분석 | −1.7%p, 95% CI [−14.1, +16.1] | 결론 불가 |

H1/H2는 두 주요 비교에 대한 Bonferroni 보정으로 각각 97.5% 구간을 사용했다.
토폴로지 조건을 유지하며 사례와 replica를 재표집하는 paired hierarchical bootstrap 4,000회를 사용했다.
이름 변경 전후 격차 감소라는 H1 보조 지표도 +8.3%p(95% CI [+4.0, +12.3])였다.
이 결과는 ID 의존성이 성능 저하의 한 원인임을 뒷받침하지만, 유일한 원인임을 증명하지 않는다.

## 정확도와 일반화에서 얻은 결론

- 같은 original 설정에서 Mesh 6 Exact는 Star 학습 **19.7% → 혼합 학습 61.0%**였다. 학습 구조를 다양화한 효과가 확인된다.
- 혼합+증강도 원래 이름의 Mesh 6 **71.0%**에서 Mesh 10 **12.7%**, Random 10 **7.0%**로 낮아진다. 작은 구조에서의 개선을 큰 네트워크의 해결로 확대할 수 없다.
- 혼합 학습의 Star 6에서 original은 원래/변경 이름 **98.0% / 74.3%**, augmented는 **84.0% / 83.0%**였다. 이름 변화에 강해지는 대신 익숙한 조건의 정확도가 낮아지는 절충이 있다.
- 혼합+증강의 원래 이름 조건별 전체 평균에서 장애 유형별 Exact는 Device **55.2%**, Performance **58.7%**, Misconfiguration **24.5%**, Link **63.2%**다. Misconfiguration은 혼합+original의 **41.5%**보다 낮아, 증강을 모든 장애에 유리한 처방으로 볼 수 없다.
- Rule은 800개 사례 모두 정답이었다. 이 시뮬레이터에서는 도구 관측으로 풀 수 있는 사례를 학습 정책이 놓친다는 뜻이다. 실제 네트워크의 Rule 성능을 보장하는 결과는 아니다.

표의 세부 조건 값은 3개 replica 평균이다. 큰 Star 등에서는 replica 간 표준편차가 크므로 [전체 결과표](../../../../netheal-topology-generalization/results/factorial_v3_20261008/report.md)의 평균±표준편차를 함께 봐야 한다.

## 진단 운영 지표에서 얻은 결론

아래는 원래 이름 조건의 8조건·3개 replica를 동일 가중 평균한 값이다. Rule은 모델 학습 반복이 없다.

| 정책 | Exact | 오진 | 시간 초과 | 도구 호출 수 | 반복 호출 비율 | 상대 도구 비용 |
|---|---:|---:|---:|---:|---:|---:|
| Rule | 100.0% | 0.0% | 0.0% | 6.33 | 0.0% | 6.71 |
| Star+original | 29.8% | 20.5% | 49.6% | 24.04 | 65.9% | 18.61 |
| 혼합+original | 47.3% | 42.8% | 9.9% | 7.62 | 39.6% | 8.26 |
| 혼합+removed | 49.7% | 27.9% | 22.4% | 13.55 | 48.4% | 11.76 |
| 혼합+augmented | 50.4% | 14.0% | 35.6% | 18.92 | 49.3% | 16.74 |

혼합+original은 적은 호출로 종료하지만 오진이 많다. 혼합+증강은 오진이 줄어드는 대신 시간 초과와 호출 비용이 커진다.
따라서 정확도 하나 또는 종료 속도 하나로 최적 정책을 고를 수 없다. 상대 비용은 설정된 도구 가중치이며 실제 요금이 아니다.
단계별 진단과 반복 호출도 기록했지만, 장애 복구 행동을 수행하지 않아 **실제 복구시간(MTTR)은 측정하지 않았다**.

CPU 의사결정 p95의 조건·replica 평균은 원래 이름의 학습 정책 약 **3.4–3.8 ms**, Rule 약 **0.12 ms**였다.
이는 해당 실행 환경에서 측정한 정책 결정 시간이며 실네트워크 왕복 지연, 서비스 처리량, 운영 SLA를 대신하지 않는다.

## 네트워크 지표에서 얻은 결론

정책과 독립적으로 모든 노드 쌍을 5회씩 측정한 공통 probe를 사용했고 이 결과를 정책 입력에 제공하지 않았다.
도달성/ping 실패율, 성공 probe의 지연 평균과 에피소드별 p95, 건강 상태와의 비교, 연속 지연 차이, 카운터 관측 범위 및 조건부 손실을 보고했다.

예를 들어 Linear 6의 ping 실패율은 **32.4%**, Random 10은 **6.4%**였다.
그런데 혼합+증강의 원래 이름 Exact는 각각 **92.3%**, **7.0%**다.
즉, 통신 실패가 많이 보이는 네트워크가 반드시 더 진단하기 어려운 것은 아니다. 증상 크기와 원인 식별 난도는 구분해야 한다.
이 비교는 조건 간 기술 통계이며 ping 실패율이 정확도를 인과적으로 결정한다는 검증은 아니다.

성공한 ping의 지연 통계에는 응답하지 않은 경로가 제외된다. 연속 지연 차이는 **실제 packet-level jitter가 아니며**, 카운터 손실은 관측 가능한 범위에 조건부다.
실제 트래픽 처리량·goodput·혼잡 부하·장애 탐지 지연·복구 후 서비스 정상화는 아직 검증하지 않았다.
네트워크 probe는 공통 사례의 특성이므로 정책에 따라 네트워크 품질이 개선됐다는 주장도 하지 않는다.

## 신뢰 범위와 남은 공백

이번 실행은 사전 고정 가설에 대한 통제 비교를 보완했다. 그러나 v2에서 문제를 발견한 뒤 설계한 후속 실험이며, 외부 사전등록 또는 독립 연구팀 재현은 아니다.
3개 replica에서 데이터 수집 seed와 모델 초기화가 함께 바뀌므로 두 변동 원인을 분리 추정하지 못한다.
표본 검정력 분석을 하지 않았고, 고정 학습 예산에서의 효과이지 모든 모델을 최적으로 튜닝한 비교가 아니다.
v2와는 update 예산 등이 달라 v2→v3 수치를 통제된 개선 전후로 비교하면 안 된다.

다음 항목은 **미실행** 상태다.

1. 정상 사례를 포함한 장애 존재 탐지: false positive rate, precision/recall, PR-AUC, 오경보/시간, 탐지 지연. 현재는 장애가 항상 있어 정상 상태 오경보를 추정할 수 없다.
2. 증거 개입: 같은 사례에서 필요한 관측을 제거·교체했을 때 판단이 바뀌는지 검증해 증거 사용과 패턴 암기를 구분한다.
3. 노이즈·관측 누락·복합 장애 및 별도 생성 분포/실장비 검증.
4. 실제 트래픽 부하와 복구를 포함한 throughput, packet loss, RTT/jitter, MTTR 측정.

다음 실험에서는 위 항목의 가설과 판정 기준을 다시 먼저 고정하고 **새 평가 seed**를 사용해야 한다.
이번 평가를 보고 모델을 수정한다면 이번 사례는 개발 자료가 되므로 동일 사례에서의 개선만으로 새 검증을 주장하지 않는다.
