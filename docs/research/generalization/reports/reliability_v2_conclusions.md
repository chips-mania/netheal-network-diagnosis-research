# 신뢰도 보완 재실험: 결론과 다음 연구 방향

2026-10-08 완료. **3개 학습 seed, 8개 조건 × 200개 공통 사례, 총 35,200회 진단 평가**를 수행했다.
평가 횟수에는 같은 사례를 여러 모델·seed로 반복한 것이 포함되며, 독립 시나리오는 1,600개다.
18개 체크포인트와 학습 데모, 에피소드 원자료, 환경 버전, 소스·모델 해시를 보존했다.

## 무엇을 보완했는가

실제 링크 up/down과 관측 전 지연을 정책 입력에서 제거했다. 정책은 명목 토폴로지와 도구로 얻은
증거만 받는다. PublicView로 시뮬레이터 내부 상태를 전달하지 않고, Rule의 내부 상태 접근도
제거했다. 잘못된 시간 속성 때문에 0이던 단계 특징과 미발견 노드를 발견 상태로 표시하던 부분도 수정했다.

GNN과 새 MLP에 동일한 성공 데모·특징·pointer 행동·평가 사례·학습 update 수를 제공했다.
기존 Mesh의 MLP 0% 대체값을 사용하지 않고 실제로 Mesh를 평가했다.
진단 가중치와 진단 샘플링을 분리하고, 같은 update만큼 추가 학습한 대조군을 넣었다.
다만 파라미터 수가 같은 비교는 아니다(GNN 85,643, MLP 732,939; 선언된 학습 가능 파라미터 수).

평가 seed는 학습 seed 영역과 분리했다. 학습 seed 11/22/33의 결과를 모두 보고하고,
동일 사례·학습 seed의 의존성을 반영한 paired bootstrap을 계산했다.
고정 데이터셋 하나의 최적화 변동성을 측정한 것이며, 데이터 수집 seed까지 바꾼 검증은 아니다.

## 1. 크기 일반화의 상대적 이점은 있으나 충분한 정확도는 아니다

| 모델 | Star 6 | Star 8 | Star 10 | Star 12 | Mesh 6 |
|---|---:|---:|---:|---:|---:|
| 규칙 정책 | 100.0 | 100.0 | 100.0 | 100.0 | 100.0 |
| 같은 입력 MLP | 99.2 | 19.8 | 14.3 | 4.8 | 23.2 |
| GNN 기본 | 100.0 | 90.8 | 60.7 | 51.0 | 22.3 |
| GNN 추가 학습만 | 100.0 | 91.8 | 66.3 | 31.0 | 15.0 |
| GNN 진단 샘플링만 | 99.8 | 93.2 | 80.0 | 40.0 | 23.0 |
| GNN 가중치+샘플링 | 99.8 | 92.0 | 64.8 | 54.0 | 22.8 |

단위는 3개 학습 seed의 평균 Exact(%). 표준편차는 전체 보고서에 있다.

Star 10에서 GNN 기본−MLP는 +46.3%p이고 비교 구간은 [+37.5, +55.3]%p다.
이는 **이 입력 표현과 모델 구성에서** GNN이 크기 변화에 유리하다는 근거다.
모든 MLP나 모든 그래프 모델에 대한 일반 명제는 아니다.
GNN도 Star 10에서 약 39%를 실패하므로 실용적 신뢰성이 확보됐다고 할 수 없다.

## 2. 기존 Generic commit 우위 해석은 수정해야 한다

동일 추가 update 대조군의 Star 10 Exact는 66.3%, 가중치+샘플링 결합은 64.8%다.
차이는 −1.5%p, 구간은 [−18.2, +14.5]%p로 일관된 개선을 확인하지 못했다.

샘플링만 적용하면 Star 10은 80.0%로 대조군보다 +13.7%p
([+1.3, +28.5]%p)였다. 그러나 Star 12는 40.0±32.9%로 불안정하다.
따라서 **샘플링은 유망한 후보지만 전 크기에서 검증된 해결책은 아니다.**
테스트 결과를 본 뒤 고른 최상 모델의 수치를 최종 일반화 성능으로 확정하지 않는다.
구간은 탐색적 비교이며 다중 비교 보정이 없고 학습 seed도 3개뿐이다.

## 3. 토폴로지 전이의 병목은 여전히 크다

GNN 기본은 Linear 6에서 18.8%, Mesh 6에서 22.3%, Random 6에서 16.5%다.
Mesh에서 새 MLP는 23.2%로 GNN 우위도 확인되지 않는다.
동일 조건의 규칙 정책은 100%이므로, 이 평가 범위의 실패를 증거가 원천적으로 부족한
문제로만 설명할 수 없다. Star 데모에서 학습한 정책의 전이 실패가 주요 원인으로 보인다.

다음 우선 실험은 같은 총 데모 예산의 Star-only 대 Star+Linear 학습,
완전히 분리한 Mesh/Random 최종 평가다. 이번에는 해당 다중 계열 재학습까지 수행하지 않았다.

## 4. 노드 순위 특징 의존도가 높다

Generic의 Star 6은 순위 특징 교란 전 99.8%에서 60.2%로,
Star 10은 64.8%에서 27.8%로 하락했다.
Star 10 차이는 −37.0%p ([−57.0, −12.0]%p)다.

네트워크 구조만으로 일반적인 진단 절차를 배웠다고 보기 어렵다.
다만 이번 검사는 ID 순위 숫자의 재배치이며 실제 장비 이름 변경이나 전체 그래프의
동형 치환 검사는 아니다. 학습 중 순위/노드 순서 증강, 순위 특징 제거,
관측에서 유도한 장애 후보 특징의 효과를 다음에 분리해야 한다.

## 5. 운영 비용: 오진뿐 아니라 반복 도구 호출이 중요하다

Star 10의 GNN 기본은 도구 평균 10.79회, 반복 도구 비율 40.6%,
오진 제출 26.5%, 미제출 timeout 12.8%였다.
규칙 정책은 도구 6.25회로 100%를 맞혔다.

Mesh 6에서 GNN 기본은 도구 18.07회, 반복 79.5%, 오진 제출 38.8%,
미제출 timeout 38.8%였다. 정확도만 보면 드러나지 않는 운영 낭비다.
성공한 사례만의 진단 단계가 짧다는 이유로 효율적이라고 결론내리지 않았다.

추론 지연도 별도로 측정했다. Star 10의 GNN 기본 정책 결정 p95는
seed별 p95 평균 1.352ms, 규칙 정책은 0.088ms였다.
이는 단일 CPU·로컬 실행시간이며 실장비 진단 시간, 네트워크 RTT, LLM API 시간과 다르다.

## 6. 네트워크 품질: 지연·연결 실패·손실을 함께 봐야 한다

진단 정책과 독립적으로 모든 ordered node pair에 5회씩 ping했다.
원본 장애 네트워크와 같은 인스턴스의 장애를 제거한 반사실 네트워크를 비교했다.
측정 결과는 정책 입력에 넣지 않았다.

- Star 10: ping 실패 15.3%, 사례별 성공 ping 지연 p95 평균 18.25ms.
  정상 반사실 p95 평균은 8.13ms.
- Linear 6: ping 실패 30.1%, 사례별 지연 p95 평균 21.66ms.
- Random 6: ping 실패 9.3%. 토폴로지별로 서비스 영향도 크게 다르다.
- Star 10의 명시적 패킷 카운터가 있는 호출만의 손실률은 11.0%였다.
  카운터 제공 비율은 95.0%이므로 이를 전체 손실률로 쓰면 일부 장비-down 실패를 놓친다.
- Star 크기가 커질수록 전체 쌍의 실패율은 낮아졌지만 학습 진단 성능은 낮아졌다.
  장애가 영향을 미치는 쌍의 비중과 진단 정책의 일반화 난도는 다른 지표다.

지연은 성공 ping에 조건부이며, 모든 쌍이 실패한 사례에는 지연값이 없다.
평균 지연만 보면 실패한 통신을 제외해 상태가 더 좋아 보일 수 있다.
그래서 실패율과 지연 분포를 함께 제공한다.

NetHeal은 경로 지연 합에 ±10% 합성 잡음을 넣고 패킷 카운터도 주로 0%/100% 손실만 표현한다.
실제 큐잉·혼잡·전송률 실험은 아니다.
동일 pair 연속 지연의 절댓값 차이를 기록했지만 표준 IPDV라고 부르지 않는다.
지연·손실·지연변동의 표준 정의는
[RFC 7679](https://www.rfc-editor.org/info/rfc7679/),
[RFC 7680](https://www.rfc-editor.org/info/rfc7680/),
[RFC 3393](https://www.rfc-editor.org/info/rfc3393/)를 참고했다.

## 7. 약한 장애와 정답 위치 선택도 별도 문제다

경미한 지연 장애 조건에서 Rule 전체 Exact는 93.5%이며
Performance 장애만 보면 74.0%였다. 유형 macro F1은 1.0이므로
이 조건에서는 유형 분류가 맞아도 위치 선택이 틀릴 수 있음을 보여준다.

GNN 기본 전체 Exact는 기본 Star 10의 60.7%에 비해 경미 조건에서 49.3%였다.
두 조건은 다른 평가 사례 seed를 사용하므로 이 차이를 장애 강도 하나만의
짝지은 인과 효과로 해석하지 않는다. 향후 동일 네트워크·위치에서 강도만 바꾸는 시험이 필요하다.

## 이후 일반 LLM, laya/jev와 비교할 때

현재는 JSON 공개 관측/행동 어댑터와 모의 외부 정책의 공통 평가 연결까지 구현·시험했다.
실제 일반 LLM 또는 laya/jev 추론을 수행하지 않았고, laya/jev의 정확한 모델 식별자는 확인되지 않았다.

우선 같은 inventory·특징·도구·40-step 예산을 주는 비교를 한다.
원시 전체 도구 텍스트나 추가 traceroute를 제공하는 확장 비교는 별도 조건으로 표시한다.
모델/프롬프트 버전, API 실패, 형식 오류, 재시도, input/output tokens, 비용,
정책 결정 p50/p95, 오진·미진단·도구 비용을 함께 기록한다.
현재 어댑터는 공급자 중립 계약이며 실제 API 타임아웃·오류 집계 실행기는 후속 구현 사항이다.

## 검증 및 남은 한계

7개 회귀 테스트와 소규모 end-to-end smoke 실행을 통과했다.
완료 산출물 검증에서 35,200개 에피소드, 1,600개 공통 사례, 18개 체크포인트,
85개 실행 시점 소스의 해시를 확인했다.
모델별 같은 사례의 정답 일치, 장애별 평가 수, 요약 통계 재계산, 비교군 update 수 일치도 확인했다.

정상 무장애 오탐률, 동시 다중 장애, 실제 처리량/굿풋, 실제 packet-level jitter,
MTTR/복구율, SLA 위반 시간, 실장비·에뮬레이터 전이는 미측정이다.
이 항목들을 0으로 채우거나 현재 진단 실험에서 검증됐다고 주장하지 않는다.

현재 결론은 **관측 기반 절차 모방과 일부 크기 전이는 가능하지만,
새 토폴로지·순위 특징 교란·약한 장애에 대한 신뢰도는 아직 충분하지 않다**이다.
재실험은 결과의 근거를 강화했으며, 모델 자체의 모든 부족함을 해결한 것은 아니다.
